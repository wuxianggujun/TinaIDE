# 真机课程与代码理解验收

适用：包含课程自动验收、双向调用导航和函数流程图的 TinaIDE 0.19.5 Debug。按下面顺序沿用一个
`native_lab` 项目测试。代码取自 App 内“C++ 完整实操路线：从项目到运行”的正文和逐级提示，
这里仅记录测试动作与预期结果，不复制课程代码。

## 1. 准备项目并完成第一章

1. 打开 App，确认原项目仍在；新建单独的 **CMake 可执行程序**，命名 `native_lab`，使用 C++17。
2. 在首页“教程”打开 **C++ 完整实操路线：从项目到运行**，进入 **实践 1：从项目到运行**。
3. 按正文设置根目录的 `CMakeLists.txt` 与 `main.cpp`，展开三次提示，使用最后提示的两行输出版本。
   代码块的复制只复制文字，需要回编辑器粘贴。不要同时保留第二个参与构建的 `main()`。
4. 按提示准备原生工具链与 sysroot。运行配置选择 **原生 CMake**、**终端**输出、`native_lab` 目标。
5. 在编辑器更多菜单或命令面板选择 **验收当前课程章节**，点击 **保存、构建并验收**。

预期：构建成功；`Hello, TinaIDE!` 和 `First change` 的输出检查通过，显示本章完成已保存。
返回教程后第一章有完成标记，下一章可进入；退出、重新打开 App 后进度仍在。

源码路径和两个参考文件见 [第一章课程资产](../../feature/help/src/main/assets/tutorial-course/ide-workflow.md)。

## 2. 验证输入、错误反馈与自动保存

1. 在教程进入 **实践 2：C++ 变量与控制流**。沿用同一项目，按正文与提示改为终端输入数量、
   校验范围，并在总价至少 100 时减去 10。
2. 先把折扣临时改为减 20，执行本章验收。预期显示实际输出不符，不能把这次失败当作通过。
3. 将折扣改回减 10，先不点保存，直接重新验收。验收应先保存编辑器内容，再重新构建并验证：

| 输入 | 预期输出行 | 退出码 |
| --- | --- | --- |
| `9` | `total=90` | 0 |
| `10` | `total=90` | 0 |
| `11` | `total=100` | 0 |
| `abc` | `expected integer` | 1 |
| `-1` | `invalid count` | 1 |

4. 成功后关闭并重开 `main.cpp`，检查减 10 的修改已保存；返回教程检查本章进度。
5. 临时删除一条语句的分号后再次验收。预期构建失败，构建日志能定位错误，旧程序输出不能
   被当作新结果。恢复分号后重试应成功，运行按钮不能一直卡在忙碌状态。

已完成章节再次验收失败时，不会自动删除原来的完成标记；应检查本次验收窗口的结果。
界面输入显示为空时，表示该用例没有标准输入。输出匹配只验证规定的结果，其他边界仍按课程练习。

代码片段见 [第二章课程资产](../../feature/help/src/main/assets/tutorial-course/cpp-basics.md)。

## 3. 验证类、方法与调用导航

1. 进入 **实践 3：函数与多文件**，按正文及最后提示创建 `pricing.h`、`pricing.cpp`、`main.cpp`，
   在 CMake 中加入实现；完成 `discountedTotal` 练习。
2. 打开大纲，查找 `totalPrice` 和 `discountedTotal`，检查签名、搜索和点击跳转。
3. 把光标放在 `totalPrice` 名称上，执行调用层次的“谁调用了它”操作；应能找到
   `discountedTotal` 内的调用位置。
4. 把光标放在 `discountedTotal` 名称上，执行 **此方法调用了谁**；应显示 `totalPrice`，
   点击后应跳到被调用方法的定义。
5. 跟课程进入 **实践 5：对象与资源生命周期** 后，检查大纲中 `OrderLedger` 与其 `itemCount`
   方法的层级；折叠类、按方法签名搜索、点击方法，位置都应正确。

这些功能需要语言服务就绪。首次配置/构建后等待 clangd，查询失败时重试；“没有结果”与服务错误
应有不同反馈。当前调用列表只展示一层关系。

课程来源：[函数与多文件](../../feature/help/src/main/assets/tutorial-course/cpp-functions.md)、
[对象与资源生命周期](../../feature/help/src/main/assets/tutorial-course/cpp-raii.md)。

## 4. 验证流程图与手机交互

1. 在 `pricing.cpp` 将光标放进 `totalPrice` 函数体，打开 **当前函数流程图**。
2. 预期参数检查有真假分支，分别连接错误返回和乘法返回。点击返回节点应回到对应源码行。
3. 重新打开图，操作缩放按钮和横纵滚动；再复制 Mermaid，粘到新建的文本文件中，检查有
   `flowchart TD` 和函数中的条件。
4. 关闭图，把条件上限从 100 改成 90，先不保存，再生成。图中应读取当前编辑内容并显示 90。
   完成后恢复 100。光标放到函数外或临时写入无效语法时，应显示无法生成，App 保持可用。
5. 横屏、竖屏各看一次：弹窗应能关闭，按钮应可点击，文字不应被键盘挡住；返回编辑器后仍能输入。

暂不支持的复杂语法会明确失败；流程图展示语法流程，不展开跨函数行为或完整宏语义。

## 5. 验证超时、取消和恢复

在完成输入练习后，临时在 `main()` 开头加入 `for (;;) {}`，其余代码保留：

1. 执行验收，等待程序开始运行。预期约 5 秒后该次运行超时；本章若有多个用例，可能分别等待
   每个用例的超时，以用例结果中的超时提示为准。
2. 再执行一次，在运行中点击窗口的 **关闭**。窗口应关闭，随后可重新发起编译或验收。
3. 删除临时死循环，重新验收。预期恢复成功，无须强制停止 App 或重启手机。

发生问题时记录：测试步骤编号、当前章节、运行配置、输入、预期与实际结果；附相关界面截图，
编译问题再附构建日志中的第一条有效错误及相邻几行。
