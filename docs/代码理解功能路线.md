# C++ 代码理解功能路线

核对日期：2026-11-19。本文记录当前源码能力及建议实现范围；未列为完成的项目仍需开发与验收。

## 当前能力与缺口

| 能力 | 当前源码状态 | 需要补齐 |
| --- | --- | --- |
| 当前文件的类和方法 | `OutlineContent` 已消费 LSP 层级符号，支持搜索、折叠、点击跳转 | 方法签名、返回类型、访问级别、当前方法定位及断开 LSP 时的明确状态 |
| 项目符号查找 | `SymbolsContent` 已支持 LSP 搜索与本地项目索引；本地索引已补齐作用域、成员位置和重载，查询移至后台 | 跨文件声明/定义关联、访问级别和语义级类型归属 |
| 谁调用当前方法 | `LspNavigationService.callHierarchyIncomingCalls()` 已接入并显示位置列表 | 出向调用、保留调用节点关系、展开多层调用与递归标识 |
| 单函数控制流程图 | 未发现 C++ 控制流提取器或生成入口 | AST 到图模型、布局、源码定位、更新与导出 |
| Mermaid 图形预览 | `MermaidDiagram` 当前使用 `CodeBlock` 显示源码 | 实际图形渲染。不能把现有组件当成可用的流程图查看器 |
| 继承与实现关系图 | 已有跳转到类型/实现的导航能力，未接入 LSP type hierarchy | 基类/派生类树、跨文件定位、关系图展示 |

本地 C++ 索引已移除按类型和名称合并重载的逻辑，保留成员所属作用域、签名和声明位置；
不再进入函数体提取参数和局部变量。文件事件会刷新或移除索引，缓存完整保存签名、注释和作用域。
这些改进属于语法索引；跨文件类型判定、模板实例化与声明/定义配对仍需 clangd 的语义能力。

## 推荐实施顺序

### 第一阶段：类与方法浏览

沿用现有大纲和符号入口，补齐 `namespace → class/struct → constructor/destructor/method/field`
层级，展示参数、返回类型、`const`/`static` 等签名信息；点击节点跳到准确源码位置。

先修本地索引的身份与作用域：保留限定名、签名和位置，区分重载、声明和定义，避免局部变量
进入全局目录。clangd 可用时优先使用语义信息；本地 AST 提供语法层面的回退，不推测模板实例化结果。

验收：嵌套命名空间、不同类的同名方法、重载、类外定义、构造/析构、操作符、模板、中文注释、
未保存修改；检查跳转位置和切换文件后的旧结果失效。

### 第二阶段：调用关系

先补“此方法调用了谁”，与现有“谁调用了此方法”组成双向浏览；随后按需展开树或图，支持
点击调用点回到源码。递归节点只引用已有节点，避免无限展开；设置深度和节点数上限。

调用关系来自 LSP Call Hierarchy，不能用 `references` 的位置列表冒充调用边。虚调用、函数指针
等目标不确定时保持未知，不补造确定的调用关系。

### 第三阶段：单函数流程图

从当前方法开始支持顺序语句、`if/else`、`switch`、`for/while/do`、`break/continue/return`。
每个节点保存源码范围，图中点击节点可回到编辑器；支持缩放、平移、重新生成和导出。

首版使用 Tree-sitter 的语法树生成结构化流程图。异常处理、`goto`、宏展开及条件编译需要单独
建模；未覆盖的语法明确标识，不能生成看似完整但含义错误的图。若未来需要编译器级 CFG，
再引入基于真实编译参数的 Clang 分析管线。

图模型与渲染器分离：可先用 Compose 绘制节点与连接线，并导出 Mermaid 源码；若选择 Mermaid
运行时渲染，需要固定并随包分发运行时、完成许可与离线加载验证。目前没有可直接复用的完整渲染器。

## 完整交互与教程衔接

编辑器选中类 → 浏览成员和方法签名 → 选中方法查看调用者与被调用者 → 打开该方法的流程图 →
点击图中节点返回对应源码。入口沿用编辑器大纲与导航动作，保留当前文件、方法和阅读位置。

配套教程以同一个 C++ 示例项目串起以上步骤，让用户修改条件或循环后重新生成图并核对变化；
帮助文档仅说明入口、操作、支持语法与失败处理，课程通过链接引用这些说明，避免复制内容。

## 模块与数据流

- `core:lsp` / `core:editor-lsp`：符号与调用关系协议适配，复用既有会话、超时和取消机制。
- `feature:editor`：代码结构、控制流分析、图模型和交互状态；复用当前符号 provider 与项目索引。
- `app`：编辑器动作入口、面板装配、源码跳转；不放解析算法。
- `editor-kit`：继续提供通用文本与语法树能力，不反向依赖宿主的图表、配置或 i18n。

数据流：当前文档快照与版本 → LSP/AST 分析 → 符号或图模型 → 面板 → 源码导航。
状态区分未支持、分析中、可用、结果过期和失败；文档修改后旧版本分析结果不得覆盖新版本。
优先使用内存中的版本缓存，当前需求不增加数据库表或第二套项目索引。
