# 编辑器基础

本文基于当前工作台实现整理，描述的是 TinaIDE 现在的编辑体验，而不是传统桌面 IDE 的菜单式布局。

## 工作台布局

典型的编辑工作台可理解为：

```text
┌──────────────────────────────────────┐
│ 顶部操作：保存 / 运行 / 构建 / 调试  │
├──────────────┬───────────────────────┤
│ 文件树抽屉   │ 标签栏                 │
│ 项目目录     ├───────────────────────┤
│              │ 编辑区域               │
│              │ 多标签切换             │
├──────────────┴───────────────────────┤
│ 底部面板：诊断 / 构建日志             │
│ 更多菜单：大纲 / 符号 / 书签 / Git    │
└──────────────────────────────────────┘
```

终端不是常驻在底部面板里的主要标签，而是作为 **独立终端页面** 使用。

## 返回与临时面板

返回操作会优先关闭当前临时 UI：展开的下拉菜单先关闭；底部面板展开时先收起面板；文件树抽屉打开时先关闭抽屉。只有这些临时 UI 都关闭后，返回才会进入未保存修改确认或退出工作区流程。

## 打开文件与切换标签

当前最常用的文件操作方式有：

- 从 **文件树** 打开文件
- 在 **标签栏** 间快速切换多个已打开文件
- 关闭当前标签或关闭全部标签

如果你使用硬件键盘，还可以在 **设置 → 快捷键** 中自定义标签切换与关闭行为。

## 常用编辑动作

当前工作台最稳定、最高频的编辑能力包括：

- **保存当前文件 / 保存全部**
- **撤销 / 重做**
- **项目内搜索与替换**
- **书签切换与跳转**
- **格式化文档**
- **多标签编辑**

## 代码智能能力

在语言服务工作正常时，编辑器可以提供这些能力：

- 代码补全
- 语义诊断
- 跳转到定义
- 查找引用
- 符号与大纲视图
- 部分场景下的快速修复 / 重命名

如果这些能力没有生效，优先检查：

- 项目是否已经成功构建过
- 是否存在可用的 compile_commands.json
- clangd / 远程 LSP 配置是否正常

## 底部面板怎么看

底部面板默认只显示 **诊断** 和 **构建日志**。**大纲**、**符号**、**书签** 和 **Git** 可从底部面板的更多菜单或对应命令按需打开；打开后会临时出现在标签行中。

### 构建日志

用于查看：

- 编译输出
- 链接错误
- 运行前后的构建细节

构建失败后，工作台会保持在 **构建日志**，方便查看编译器或链接器的原始输出。

### 诊断

用于查看：

- clangd 上报的错误与警告
- 点击后可快速定位到代码位置

诊断来自 LSP，可能为空，也可能暂时落后于刚完成的构建结果。排查构建失败时应以 **构建日志** 为准。

### 大纲 / 符号

**大纲**展示当前文档中的结构，适合在单个文件里快速定位函数、类和结构体。**符号**提供项目级符号搜索，适合跨文件查找并跳转到目标声明。

这两个面板都按需打开，不会默认占用底部标签栏空间。

### 书签

适合在长文件或来回修改多个位置时快速跳转。

### Git

底部 **Git** 面板用于查看提交日志；抽屉中的 **Git** 页面用于查看工作区变更和暂存状态。

### 运行输出

当前运行模式会把控制台结果送到独立 **Terminal**，图形程序则进入 **SDL**。底部面板不会显示没有数据来源的空 **运行输出** 标签。

## 文件查看器

当前工作台已经明确接入的专用查看器类型包括：

- **大文件文本**
- **图片**
- **Hex**

**JSON** 和 **Markdown** 默认使用代码编辑器打开，保留编辑与语法高亮能力；大文本、图片和二进制文件会使用更合适的专用查看器。

## 与终端的配合方式

如果你要执行以下操作，建议切换到独立终端：

- 手写 cmake / make 命令
- 运行 Git 命令
- 执行脚本
- 进行 SSH / rsync / 远程开发相关操作

## 建议的上手顺序

1. 学会用文件树打开文件
2. 熟悉标签切换
3. 观察构建日志与诊断面板
4. 熟悉书签与符号跳转
5. 再进一步学习终端、调试与 Git
