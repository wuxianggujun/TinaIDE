# LSP 概述

LSP（Language Server Protocol）是 TinaIDE 当前代码智能能力的核心基础。对 C / C++ 开发来说，它决定了补全、诊断、跳转和很多“像 IDE 一样”的体验。

## LSP 在 TinaIDE 里负责什么

基于当前实现，语言服务器相关能力主要包括：

- **代码补全**
- **诊断信息**
- **Quick Fix（快速修复）**
- **条件式 Fix All（批量修复）**
- **跳转到定义**
- **查找引用**
- **重命名**
- **签名帮助**
- **Inlay Hints**
- **Semantic Tokens（语义高亮）**
- **折叠范围**

其中多数能力都围绕 **clangd** 展开。

## 本地 LSP 与远程 LSP

### 本地 LSP

分析在当前设备完成。

优点：

- 不依赖网络
- 配置相对简单
- 隐私边界更清晰

局限：

- 更吃手机性能
- 大项目索引和补全可能更慢

### 远程 LSP

分析在电脑侧完成，手机主要承担编辑与展示。

优点：

- 更适合大型项目
- 补全和索引通常更快
- 能减轻手机端内存压力

局限：

- 需要网络环境
- 需要额外配置主机、端口和同步方式

## 为什么 `compile_commands.json` 很关键

clangd 想正确理解工程，必须知道真实编译参数。

这份编译数据库会影响：

- 补全准确度
- 头文件解析
- 宏定义识别
- 跳转和引用结果
- 诊断质量

所以当你觉得 LSP “不准”时，第一优先级几乎总是先检查工程构建配置，而不是盲目重启编辑器。

## 查看当前 C/C++ 编译上下文

打开 C 或 C++ 文件后，点击编辑器底部状态栏的语言服务状态，可以查看当前文件实际交给 clangd 的编译上下文，包括：

- 本机或远程 clangd 模式
- `compile_commands.json` 的路径、来源和更新时间
- 当前文件的命令是精确匹配、从相关源文件推断，还是没有匹配
- 编译器、C/C++ 标准、Target、工具链、NDK Runtime 和 Sysroot
- 头文件搜索路径、预处理宏和完整编译参数

如果项目能够编译，但补全、头文件解析或诊断仍不正确，先核对这里显示的参数是否与真实构建一致。必要时使用 **刷新并重载** 重新准备编译上下文并连接 clangd。

远程 LSP 的编译命令由远端语言服务管理，因此本机只显示连接和工作区状态，不会展示无法验证的远端编译参数。

## 诊断与快速修复

“问题”面板会向当前文件的语言服务器确认某条诊断是否真的存在可用 Quick Fix。只有服务器返回至少一个可执行修复时，诊断项才显示 **查看修复**；普通错误、仅提供重构操作的诊断或服务器明确禁用的修复不会显示这个按钮。

没有 **查看修复** 不代表诊断无效，只表示语言服务器当前没有提供可以自动执行的修复。你仍然可以点击诊断跳转到对应位置并手动修改。若诊断来自尚未打开或语言服务仍在连接的文件，请先点击诊断打开文件；连接就绪后面板会重新检查修复能力。

编辑器菜单中的通用 **代码操作** 与诊断 Quick Fix 是两个入口：通用入口仍可显示重构和 Source Action，诊断入口只显示与当前问题直接相关的快速修复。

当当前活动文件的语言服务器明确提供可执行的 `source.fixAll` 操作时，“问题”面板会显示 **全部修复**；不支持时该入口保持隐藏。点击后 TinaIDE 会重新获取最新操作，多文件变更会先列出受影响文件和编辑数量，确认后才会应用。

## 设置入口

当前相关入口统一在：

**设置 → 语言服务器**

这里可以看到并调整的内容包括：

- clangd 补全样式
- 函数参数占位符模式
- 补全候选数量
- 补全大小写敏感
- 签名帮助
- Inlay Hints
- Semantic Tokens
- 远程 LSP 主机 / 端口 / 同步模式 / 连接测试

## 推荐理解方式

你可以把 TinaIDE 里的 LSP 理解为：

```text
编辑器输入
   ↓
语言服务器分析工程
   ↓
返回补全 / 诊断 / 跳转 / 签名帮助等结果
   ↓
编辑器负责展示与交互
```

也就是说，编辑器和语言智能是协作关系，而不是全都写死在编辑器里。

## 常见误区

### “我能编译，所以 LSP 一定没问题”

不一定。构建成功只能说明当前构建链路可用，不代表编译数据库、索引状态和语言服务配置都正确。

### “补全慢一定是手机太差”

也不一定。很多时候是：

- 编译数据库不完整
- 项目过大
- 远程 LSP 没配置好
- 当前同步模式不合适

### “LSP 只是补全”

不对。当前 TinaIDE 里的 LSP 还同时承担诊断、跳转、引用、重命名、签名帮助等多项能力。
