# 依赖包管理说明

本文基于当前包管理页源码整理，重点说明已安装包列表、Linux / Android 双平台状态、检查更新、详情页，以及批量卸载这些和当前 UI 对得上的能力。

## 先理解当前依赖包入口

**我的 → 我的包** 只列出已安装包，包含有可用更新的包。Android 或 Linux 任一侧已安装即可显示；卸载后会重新判断是否仍属于此列表。
**设置 → 依赖包** 提供完整包目录和管理操作。

它更偏向：

- 管理已经安装过的包
- 查看每个包在 Linux / Android 两侧的状态
- 做更新、卸载和详情排查

浏览新库可以打开首页 **市场 → 包管理**。它与「我的包」的筛选范围不同。

## vcpkg 包目录

**市场 → vcpkg** 按项目管理依赖。内置包通常提供预编译制品，vcpkg 提供更多上游库，但本机安装可能需要下载源码并编译。
打开后顶部是固定的工具栏，列表滚动时仍可更换项目；搜索框在市场顶栏，与插件、包两个 Tab 共用：
- 顶栏搜索按库名或描述过滤，输入后自动生效；切换 Tab 保留关键词，切换项目保留关键词。
- 列表只有一个视图：按上游声明筛选当前应用架构和静态链接条件，未声明限制的库也列入候选；已写入清单但被兼容性过滤掉的条目同样会显示，保证还能移除。
- 刷新图标重新读取本地目录，云下载图标 **下载 / 更新包列表** 获取最新目录；更新失败或取消时保留原列表。
- 项目按钮用于选择 CMake 项目；未选择项目时仍可浏览库，添加依赖时再选择。
工具提示会说明当前架构下有多少上游库因不兼容被隐藏。搜索没有匹配时，页面会区分「不存在该库」和「该库存在但声明不支持当前架构或静态链接」。
库卡片显示名称、版本和描述，并标记 **已在清单**、**已验证**、已安装版本和可升级版本。**查看详情** 打开项目状态、兼容性、目标架构和上游 `supports` 声明；卡片和详情页都可以复制库名。
点击 **添加到项目** 选择项目后，应用自动启用内置 vcpkg 并修改 `vcpkg.json`；**移出依赖清单** 会先显示确认对话框，移除后再次安装以同步安装状态。间接依赖由 vcpkg 管理。
「已安装」来自所选项目和 ABI 的实际 vcpkg 安装状态，不等同于「已添加到清单」。**已验证** 只标记 TinaIDE 在真机上完整跑通过下载、编译和链接的库（目前只有 `fmt`），其余库仅依据上游声明筛选。修改清单后底部提供两种安装方式：**安装到项目** 把依赖装进项目私有工作区；**装到共享库** 先按同样方式安装，再把该 ABI 的依赖导出到设备级共享目录，其他项目可直接复用。安装输出在独立对话框中实时滚动并支持复制；出错时列表顶部会显示可重试的错误提示，并可随时取消。
导出到共享库后，当前项目切换为共享库模式（依赖库目录指向共享路径），如需继续添加依赖，用底部的 **使用内置 vcpkg** 切回内置管理；项目私有安装工作区保留。共享库与安装索引按 ABI 写入同一代目录，完整导出后才原子切换，因此构建中不会短暂丢失旧目录。市场从当前共享索引显示实际安装版本，而不是只显示清单标记。旧版导出没有版本索引的库不会被伪造为已知版本。
共享库保留当前代与上一代，活跃构建退出后再回收更旧目录。vcpkg 生成的 CMake config 用相对前缀定位；若某个库自行把绝对路径写进 pkg-config 或 config，复用时可能提示路径不存在，在该项目重新安装一次即可。
Android 原生 vcpkg 与 git、curl、zip、unzip、pkg-config 等工具快照随 APK 提供，首次准备逐包校验解压，不依赖滚动仓库保留旧版本。库源码和 Git 对象仍按需联网获取。
更新目录或准备源码后，应用缓存仅保留当前修订和最近一个旧修订；仍在构建时延后回收，不删除其他非修订目录。
设置只保存关闭、项目清单或设备共享库模式，不保存工具或安装路径。旧手动目录和预编译配置不再读取；共享模式由应用固定定位，可在其他项目的 vcpkg 设置中选择。
平台筛选依据上游声明，不代表每个库及其依赖都已实测。实际失败原因可在构建日志查看；PRoot/Linux 与 Android 库不能混用。

新项目和已有项目的完整接入示例见 [CMake 使用 vcpkg](vcpkg-guide.md)，也可以从市场内的 **使用教程** 入口打开。

## 当前首页能做什么

顶部栏当前提供：

- 搜索
- 检查更新
- 刷新
- 选择模式
- 有更新时的 **全部更新**

如果检测到可更新包，顶部会显示数量标记，并出现 **全部更新** 按钮。

## 列表页看什么

「我的包」列表来源是**已安装包数据**；设置中的依赖包页显示完整目录。卡片上通常会看到：

- 包名
- 版本
- 简短描述
- 内置标记
- 包版本 / 上游库版本（有元数据时）
- Linux 平台状态
- Android 平台状态

### Linux 和 Android 两行是什么意思

当前卡片会把同一个包拆成两种平台状态：

- `Linux`：对应 PRoot / Linux 环境侧
- `Android`：对应 NDK / Android 侧

所以你可能会遇到同一个包：

- Linux 已安装，但 Android 未安装
- Android 已安装，但 Linux 还没装
- 两边都有更新

这不是重复显示，而是平台状态本来就独立。

### 按钮状态

每个平台当前会显示以下几类状态之一：

- **安装**
- **已安装**
- **安装中**
- **更新**

如果你只是想补齐某个平台的库，不一定要重装整个包。

## 详情页能看什么

点开某个包后，当前详情页会展示：

- 基本信息
  - 分类
  - 主页
- 平台信息
  - 安装类型
  - Linux 包名（apt 适用时）
  - 大小
  - ABI
- 版本信息
  - 包版本
  - 包修订
  - 上游项目
  - 库版本
  - 上游标签
- 依赖
- 更新日志

### 依赖是可点的

如果包声明了依赖，详情页里的依赖项当前是可点击跳转的。

这适合顺着依赖链继续排查还缺什么。

## 安装、更新、卸载时会发生什么

当前进度对话框会分阶段显示：

- Preparing
- Downloading
- Verifying
- Extracting
- Installing
- Completed / Failed

如果安装或更新成功，当前成功提示还会提醒你：

- **重新打开文件**

这是因为新装的头文件补全和编译链接效果，往往要在文件重新打开后更容易刷新出来。

## 检查更新和全部更新

当你点 **检查更新** 后，页面会收集当前可更新包。

如果有结果：

- 顶部显示更新数量
- 可以直接点 **全部更新**

全部更新会逐个执行，不是并发一次性全拉。
同一个包的 Android 与 Linux 更新分别列入任务。批量结果分别统计成功、失败和未完成项；失败或取消的更新会保留，方便重试。

## 选择模式和批量卸载

长按包卡片，或者点顶部 **选择**，可以进入选择模式。

当前选择模式支持：

- 多选
- 全选 / 取消全选
- 按平台批量安装
- 按平台批量卸载
  - 批量卸载 Linux
  - 批量卸载 Android

批量安装、更新和卸载都可以取消；已完成的项目保留，尚未完成的项目不会计作成功。

## 什么时候会看到“暂无已安装的包”

这表示当前包管理页没有读到任何已安装包。

按当前文案，下一步通常不是在这里反复刷新，而是：

1. 去首页 **市场**
2. 先安装你需要的包
3. 再回到包管理页做更新、卸载或状态查看

## 常见问题

### 为什么安装了包，补全或编译还是没变化

先检查：

1. 目标平台是不是装对了，Linux 和 Android 不要看错
2. 安装是否真的成功完成
3. 重新打开过相关文件没有
4. 构建日志里是否还有其他缺失依赖

### 为什么卸载时会警告还有别的包依赖它

因为当前卸载确认会先查询依赖它的其他包，并把结果列出来，避免你把依赖链直接拆坏。

### 为什么这里搜不到某个新包

「我的包」只显示 **已安装包**；搜索也仅在已安装项中进行。

要找新包，先去首页 **市场**。

## Android 依赖包的 include 和源码使用

Android 依赖包按产物类型使用，不按 ABI 拆成多个逻辑包。

- `header` 包：安装后会暴露包内的 `include/` 目录。重新打开相关 C/C++ 文件后，clangd 补全和单文件编译会自动加入这些头文件搜索路径。
- `source` 包：安装后同样会暴露 `include/`，但包内 `src/` 不会被 TinaIDE 自动编进你的项目。你需要在 CMake、Makefile 或项目源码配置里显式加入对应源码文件。
- `static`、`shared`、`executable` 包：安装后会暴露 `lib/` 或可执行文件目录，并根据当前设备 ABI 选择可用内容；不匹配当前设备 ABI 的包会在安装前被拦截。

例如，安装 `nlohmann-json`、`glm`、`stb` 这类 `header` 包后，可以直接在代码中 include 对应头文件。
安装 `tinyxml2`、`fmt`、`imgui` 这类 `source` 包后，还需要把包内源码加入构建。
