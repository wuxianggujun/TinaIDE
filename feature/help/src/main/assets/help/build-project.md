# 编译项目

本文描述的是 TinaIDE 当前支持的主流构建工作流：单文件、CMake、Make，以及 NDK 原生库场景。

## 当前支持的项目类型

- **单文件项目** - 适合快速编译一个 main.cpp
- **CMake 项目** - 推荐的大多数 C/C++ 工程形式
- **Make 项目** - 适合已有 Makefile 的工程
- **NDK 共享库项目** - 适合原生库开发

## NDK 共享库的运行目标

NDK 共享库模板不是“编译一个 `.so` 就结束”。

它通常包含两个目标：

- 共享库本体
- 一个用于验证共享库的测试可执行文件

因此你在点击 **运行** 时，默认可能看到的是测试程序输出，而不是直接把 `.so` 当成主程序运行。

如果你要看共享库本体的运行结果：

1. 切换到 SDL 运行模式
2. 或在运行配置里显式选择共享库目标
3. 若你刚修改过源码，先保存文件，再重新运行

## 标准工作流

最常见的流程如下：

1. 保存当前修改
2. 点击顶部的 **运行**、**构建** 或 **调试**
3. 等待构建完成
4. 在底部 **构建日志** 查看完整输出
5. 在 **诊断** 面板查看 clangd 错误与警告

构建失败时，工作台会保持在 **构建日志**，不会强制切换到诊断。LSP 诊断可能为空或暂时落后于本次构建，因此编译器和链接器的原始输出应以构建日志为准。

如果你发现“编辑器里已经是新代码，但运行结果还是旧模板”，优先检查两件事：

- 当前跑的是不是测试可执行文件，而不是共享库目标
- 修改后的文件是否真的已经保存到磁盘

需要进一步定位时，可以打开：

**设置 → 开发者选项 → 诊断日志 → 启用诊断日志 → 构建诊断日志**

开启后，日志会记录本次运行前是否触发保存、CMake 选中了哪个 target、增量构建为什么判定为 `up-to-date` 或重新构建、`compile_commands.json` 是否参与输入指纹，以及最终启动的产物路径。日志不会记录源码内容。

## CMake 项目

对于 CMake 项目，首次构建前后通常会发生这些事情：

- 进行配置
- 生成或更新构建目录
- 生成或更新 compile_commands.json
- 执行编译与链接

这也是为什么很多补全、跳转和诊断能力会在首次构建后更稳定。

## 单文件项目

单文件项目更适合：

- 语法练习
- 快速跑一个小程序
- 临时验证算法

这类项目结构最简单，但随着文件变多，建议迁移到 CMake 或 Make。

## Make 项目

如果项目已有自己的 Makefile，TinaIDE 也可以配合它工作。

适合：

- 保持现有工程结构不变
- 继续使用你已有的 Make 规则
- 在终端里执行更复杂的自定义目标

## 运行配置

当前工作台支持运行配置相关能力，常见配置项包括：

- 运行目标
- 输出模式：终端、SDL 图形运行或 NativeActivity 图形运行
- 命令行参数
- 环境变量
- 工作目录

如果你的程序需要特定输入文件、参数或环境变量，请先检查运行配置，而不是只盯着编译本身。

共享库的输出模式必须匹配入口契约：SDL 项目导出 `SDL_main`，raylib 项目保留普通 `main` 并选择 NativeActivity。仅切换模式不会改写源码入口。

## 调试

点击 **调试** 后，会进入 LLDB 相关调试流程。

适合：

- 下断点
- 单步执行
- 查看调用栈
- 查看变量

如果调试器不可用，通常说明开发环境还没部署完整，或者 Linux / PRoot 调试环境中的 LLDB 需要重新准备。基础编译和运行仍优先走 native toolchain，不要把调试环境问题直接当成默认编译链路问题。

## 终端中的自定义构建

下列场景更适合使用独立终端：

- 手动执行 cmake
- 运行 make test、make clean
- 自定义脚本构建
- 执行项目自带的工具链脚本

## 结果应该看哪里

### 构建日志

优先看这里：

- 编译器输出
- 链接报错
- 目标文件或可执行文件生成过程

### 诊断

适合看：

- 文件内具体错误
- clangd 语义告警
- 点击跳转到出错位置

诊断是 LSP 提供的辅助信息，可能为空或暂时较旧，不能替代构建日志。

### 运行结果

控制台程序的运行结果进入独立 **Terminal**，图形程序进入 **SDL**。当前没有组件写入底部 **运行输出**，因此空标签会保持隐藏。

## 常见问题

### 编译失败但编辑器没报错

可能是：

- 构建系统配置错误
- 头文件路径错误
- 链接阶段才暴露的问题

先看 **构建日志**，不要只看编辑区颜色提示或 LSP 诊断；后者可能为空或暂时落后于本次构建。

### 有补全，但运行失败

说明语言服务工作正常，但：

- 运行配置不对
- 目标程序没成功链接
- 工作目录或参数不匹配

### 调试按钮不可用或报错

先检查：

- 开发环境是否已部署完成
- 设备剩余空间是否充足
- 是否需要在设置里重新部署开发环境

### 装了依赖包，但头文件补全或编译结果还是没变化

先检查：

1. Linux / Android 平台是不是装对了
2. 安装流程是否真的成功完成
3. 相关文件有没有重新打开
4. 构建日志里是否还有别的缺失依赖

当前包管理页安装成功后，本身也会提示你重新打开文件。

## 构建进程和临时资源回收

TinaIDE 会把一次构建中的外部工具进程当成短生命周期任务管理：

- CMake、Make、单文件编译都会设置构建超时
- 超时或取消时会先结束进程，必要时强制终止
- 进程输出流会在命令结束后关闭，避免后台读线程残留
- 每次构建命令使用独立临时目录，结束后自动删除
- 旧的构建临时目录会按时间和数量做轻量清理

这里清理的是 **临时资源**，不是项目的持久构建产物。`build` 目录、`compile_commands.json`、增量构建缓存和已注册 artifact 会保留，用于后续加速与源码变更检测。需要全量删除时，请使用 CMake 清理构建目录或重新构建相关入口。
