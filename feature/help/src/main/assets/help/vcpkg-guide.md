# CMake 使用 vcpkg：从添加库到运行

TinaIDE 已内置 Android 原生 vcpkg。你只需要选择库、声明 CMake 链接并构建；工具目录和安装目录由应用管理，无需安装额外插件或填写路径。

本教程用 `fmt` 输出 `TinaIDE + vcpkg: 42`。源码项目需要 CMake，安装依赖时使用 **原生** 运行模式。配套工具随 APK 提供并校验解压；库源码首次使用时联网下载，在设备上编译。

GitHub 连接较慢时，点击 **市场右上角 → GitHub 代理**，选择预设网址或填写自己的 HTTPS 代理前缀并保存；无需进入设置。所选地址优先用于目录、源码和 vcpkg 的 Git 拉取，失败后尝试原地址。Git 拉取要求该代理支持 Git；可选的 HTTP 代理也能提供网络连接。留空网址恢复自动选择。正在进行的安装继续使用启动时的配置，取消后重试即可使用新配置。

## 1. 新建或选择项目

新项目：

1. 在 **项目 → +** 打开新建向导，选择 **CMake 可执行程序**。
2. 项目名填写 `tina_vcpkg_example`，选择 C++17 或更新标准。
3. 勾选 **使用内置 vcpkg**，再创建项目。

该选项默认关闭，只在 CMake 模板中显示。勾选后创建空的 `vcpkg.json` 并启用内置管理；模板已有清单会保留，不会覆盖。创建过程不下载或编译库。

已有项目也可以直接接入：确认项目根目录有 `CMakeLists.txt`，然后从下一步开始。在市场首次添加依赖时，应用会自动启用集成。创建时忘记勾选也可以这样补上。

单文件和 Make 项目不使用这项 CMake 集成。图形模板仍需其原有引擎依赖；启用 vcpkg 不会自动替换模板要求的内置包。

## 2. 添加 fmt

1. 打开 **市场 → vcpkg**，搜索 `fmt`。
2. 点击 **添加到项目**，选择刚创建的 CMake 项目。
3. 确认 `fmt` 卡片上出现 **已在清单** 徽标。

卡片上的 **已在清单** 表示依赖已写入项目，**查看详情** 可以核对项目状态、兼容性、目标架构和上游 `supports` 声明；卡片右上角的复制按钮只复制库名，不会修改项目。再次点击已添加的库会先弹出确认对话框，再移出清单。

应用会更新项目根目录的 `vcpkg.json`。最小清单如下；若文件已有其他依赖或配置，只合并依赖项：

```json
{
  "dependencies": ["fmt"]
}
```

“添加到项目”只修改清单。出现 **已安装** 版本号，才表示该项目和架构下已有实际安装记录。

## 3. 在 CMake 中链接库

对于本教程的新项目，将根目录 `CMakeLists.txt` 改为下面内容，并在同一目录创建 `main.cpp`。这个示例编译根目录的 `main.cpp`。

```cmake
cmake_minimum_required(VERSION 3.22)
project(tina_vcpkg_example LANGUAGES CXX)
find_package(fmt CONFIG REQUIRED)
add_executable(tina_vcpkg_example main.cpp)
target_link_libraries(tina_vcpkg_example PRIVATE fmt::fmt)
target_compile_features(tina_vcpkg_example PRIVATE cxx_std_17)
```

`main.cpp`：

```cpp
#include <fmt/core.h>

int main() {
    fmt::print("TinaIDE + vcpkg: {}\n", 42);
    return 0;
}
```

已有项目只需合并 `find_package(fmt CONFIG REQUIRED)`，并把 `fmt::fmt` 加到现有目标的 `target_link_libraries`；目标名应使用你自己 `add_executable` 或 `add_library` 中的名字。不要替换原有目标和源文件列表。

应用会自动传递 vcpkg toolchain，无需手填 `CMAKE_TOOLCHAIN_FILE`、`VCPKG_ROOT` 或库安装路径。市场包名、`find_package` 名和 CMake target 名不一定相同，使用其他库时应查该库的 CMake 用法。

## 4. 安装、构建并运行

保存两个文件，然后回到编辑器点击 **运行**。应用会先安装清单依赖、配置 CMake，再构建并运行选中的目标。

也可以在市场底部点击 **安装到项目**，在安装输出对话框中查看实时日志并复制文本；这一步不会运行用户程序，完成后仍需到编辑器构建/运行。安装失败时列表顶部会显示可重试的错误提示。在 **设置 → 编译器 → CMake 运行模式** 选择 **原生模式**；项目运行配置选择终端输出和 `tina_vcpkg_example` 目标。

预期输出：

```text
TinaIDE + vcpkg: 42
```

失败时先看 **构建日志** 中的第一个安装、配置或链接错误。取消安装会保留已经完成的库，稍后可重试。

## 5. 添加、移除和更新

- 添加其他库：在市场添加依赖，再按库文档补充 CMake 链接和源码使用。
- 移除库：在库卡片点击 **移出依赖清单** 并在确认对话框中确认，同时删除代码中的使用和 CMake 链接，再次安装/构建以同步状态。被其他库依赖的包仍可能保留。
- 更新列表：**下载 / 更新包列表** 更新可浏览的 ports 元数据；不会自动改写项目清单、升级已安装库或替换随 APK 的 CLI。工具栏的刷新图标只重新读取本地目录。
- 复用已编译的库：底部 **装到共享库** 会先安装依赖，再把当前 ABI 的库导出到设备级共享目录，并把项目切换为共享库模式。其他项目在 **项目设置 → vcpkg 依赖 → 使用设备共享依赖库** 选择复用；仍需在 CMake 中添加 `find_package` 和链接目标。需要修改清单时，用 **使用内置 vcpkg** 切回。
- 固定版本：已有 `builtin-baseline`、features 和 overrides 会保留。市场展示的是当前目录，项目最终使用的版本受自身清单和 registry 配置约束。
- 关闭集成：在 **项目设置 → vcpkg 依赖** 选择关闭。之后需要自行调整依赖库的 CMake 链接。

默认列表按上游 `supports` 声明、当前应用架构和静态链接条件筛选。上游未声明限制的库也在候选中；顶部会提示因不兼容被隐藏的上游库数量。筛选不代表所有 features、传递依赖和额外构建工具均已实测；`fmt` 有设备验收记录，其他库需要按项目实际构建验证。已下架或不兼容的已有依赖仍会显示在列表中，便于移除。

## 常见问题

| 现象 | 检查方法与处理 |
| --- | --- |
| 市场里没有这个项目 | 确认项目已在项目列表中，根目录存在 `CMakeLists.txt`；子目录里的文件不足以识别为根 CMake 项目 |
| 添加后提示找不到 fmt | 确认选择的是当前项目，检查 `vcpkg.json` 和安装日志，确保使用原生 CMake 模式 |
| 头文件存在但链接报错 | 检查是否把 `fmt::fmt` 链接到实际运行的目标；只添加清单不会修改 CMake 链接 |
| 找不到某个包 | 搜索只覆盖当前 Android 候选；如果提示该库存在但不兼容，说明上游声明不支持当前架构或静态链接。可更新目录，但不要将 Linux/Windows 库混入 Android 构建 |
| 断网时安装失败 | 浏览目录、阅读教程和准备随包工具可离线；首次获取 ports 源码、Git 对象或库源码时需要网络 |
| GitHub 下载失败或一直等待 | 在市场右上角切换 GitHub 代理；进行中的任务先取消再重试。下载代理和 Git 代理能力不同，Git 初始化失败时应检查代理是否支持 Git smart HTTP |
| 目录或仓库归档缓存损坏 | 重新更新列表，或重试安装依赖。读取缓存时会校验，无效归档会重新下载并尝试备用来源；所有来源失败时保留原列表，无需卸载应用或手工安装 vcpkg |
| 共享模式不能修改依赖 | 选择 **使用内置 vcpkg** 切回项目清单模式，再添加库；已有共享库文件保留 |

## 练习与验收

1. 把 `42` 改为 `7 * 6`，运行并确认输出相同。
2. 在 CMake 中临时删除 `target_link_libraries`，观察构建日志中的编译或链接错误；恢复后再次成功运行。
3. 再次构建，检查安装输出复用了已完成依赖。
4. 完成一次在线安装后断网，重新构建原项目；缺少新源码时的失败应保留已有目录和已安装库。
5. 向另一个 CMake 项目复用共享库，确认它实际运行成功，再把该课标记为完成。
