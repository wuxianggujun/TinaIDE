# vcpkg 依赖管理速查

TinaIDE 的 vcpkg 集成面向 Android 原生 CMake 项目。完整的添加、链接、构建与运行实操请到教程中心开启连续 C++ 实践课程；本文只解释状态、模式和排错入口。

## 状态与操作边界

- **已在清单**：依赖名称已写入所选项目的 `vcpkg.json`，不代表下载或安装已完成。
- **已安装**：当前项目与 ABI 有实际安装记录。清单变化后需重新安装/构建以同步依赖。
- **已验证**：TinaIDE 已完成相应设备上的下载、编译和链接验收；它不是对所有 features 或传递依赖的保证。
- 修改清单不会自动补齐 CMake 使用关系；CMake 仍需要 `find_package` 和 `target_link_libraries`。包名、包配置名和 target 名可能不同，按上游用法确认。

## 集成模式

- **项目内置 vcpkg**：清单和安装工作区属于当前项目。工具链、工具和路径由应用管理，不要手动设置 `CMAKE_TOOLCHAIN_FILE`、`VCPKG_ROOT` 或桌面 sysroot。
- **设备共享库**：已编译依赖按 ABI 导出，其他项目可以复用；每个项目仍须声明 CMake 包发现和 target 链接。要编辑依赖时切回项目内置模式。
- **关闭集成**：项目不再使用应用管理的依赖，需自行整理相关 CMake 引用。

## 目录与兼容性

市场目录是可浏览候选，不是当前 Android ABI 上逐库构建的承诺。列表按上游 `supports` 声明和静态链接条件筛选；无上游限制声明的库也可能显示。依赖 feature、传递库或额外构建工具仍可能不兼容。已下架/被筛掉但在清单中的依赖应先移除或改清单，不要混入 Linux/Windows 制品。

刷新按钮读取本地目录；“下载 / 更新包列表”才获取新目录，不会改写项目清单、升级已安装库或更新 APK 内工具。工具与宿主会校验并解压 APK 附带的版本；首次缺失的 ports、Git 对象或库源码可能需要网络。

连接 GitHub 较慢时，可在市场右上角配置 GitHub 代理。普通 HTTP 下载代理不一定支持 Git smart HTTP；任务使用启动时配置，修改后取消并重试。失败或取消更新时，旧目录仍可用。

## 排错速查

| 现象 | 检查方向 |
| --- | --- |
| 市场选择器找不到项目 | 项目需在项目列表中，且根目录存在 `CMakeLists.txt` |
| 加入清单后找不到包配置 | 确认当前项目、ABI、安装状态、原生 CMake 模式及 `find_package` 名 |
| 头文件可见但链接失败 | 检查实际运行的 CMake target 是否链接正确 target；仅有清单不够 |
| 包不在兼容列表 | 检查目录声明、当前 ABI、静态链接和依赖 features；不能用桌面库替代 |
| 安装或目录下载失败 | 看构建/安装日志第一条有效错误；检查网络和 Git 代理能力，取消后重试 |
| 共享模式无法编辑清单 | 切回项目内置 vcpkg 模式；共享库文件会保留 |

优先保留原项目和构建日志；不需要卸载应用、删除源码或手工复制依赖来排查。
